# Structured grounding is critical for reliable intelligence report generation with LLMs

- **Citation (IEEE):** H. Shakil, W. Armstrong, Z. H. Pugh, et al., "Structured grounding is critical for reliable intelligence report generation with LLMs," *Expert Systems With Applications*, vol. 331, Art. no. 133146, 2026, doi: 10.1016/j.eswa.2026.133146.
- **Domain:** NLP / structured report generation with knowledge-graph and spatial grounding
- **Relevance to FYP (1-5):** 3 — different domain, but strong evidence that feeding structured data (KG/metadata) into the prompt is what makes LLM reports schema-compliant and accurate — exactly the FYP's diagnosis-report problem.

## Problem
Operational intelligence reports need complete metadata schemas (16 mandatory fields) and accurate geographic coordinates; real data are restricted, and it was not known whether LLMs can reliably meet these structural requirements when generating synthetic reports.

## Data & modalities
Text plus structured inputs: knowledge graphs of entities/relations (symbolic grounding) and geographic metadata/map data (spatial grounding). 382 synthetic intelligence reports generated by GPT-3.5 and GPT-4 under four conditions: none (baseline), KG only, Map only, KG + Map.

## Method
- Recursive prompting: a tree of subtopics/follow-up questions (e.g., parameters R = 2, X = 2, Y = 3) where each node generates a focused report.
- JSON-formatted outputs with full metadata schema, embedded tables, fictional personas and classification labels.
- Dual evaluation: automated metrics (schema compliance, geographic accuracy with a pre-defined tolerance, entity grounding, lexical diversity) plus three expert raters on 20 reports (Likert 1-5: clarity, objectivity, comprehensiveness, rigor, relevance).
- Token cost analysis per configuration.

## Results
- Schema compliance 0% (baseline) → 100% with structured inputs (p < 0.001), regardless of model scale for baseline.
- Geographic accuracy 82.9% (GPT-4) and 57.4% (GPT-3.5) with grounding; unmeasurable for baseline.
- Entity grounding only 15-23% (attributed to recursive topical exploration).
- Human ratings all high (M > 4.0/5.0; 84-94% agreement, but Krippendorff's α = 0.118), so human raters missed technical failures — automated and human metrics capture different quality dimensions.
- Cost: KG + Map increases tokens per report by up to 262% (GPT-4: $12.57 vs $3.46 for baseline across 12 reports).

## Limitations
Synthetic data only; small human-evaluation sample and low inter-rater reliability; only GPT-3.5/GPT-4; modest entity grounding; increased token cost.

## Transferable ideas for the FYP pipeline
- **Text/RAG + KG:** inject structured context (a small knowledge graph of machine components → fault modes → symptoms → remedies built from TRUMPF documentation, plus the relevant machine-database record) into the prompt; expect large gains in completeness and correctness of reports.
- **LLM output:** define a mandatory JSON schema for diagnosis reports (machine ID, job, timestamp, defect, evidence list, root cause, confidence, recommended parameter change) and measure schema compliance automatically.
- **Evaluation:** combine automated checks (schema compliance, numerical/parameter accuracy, entity grounding against KG) with engineer ratings; do not rely on human ratings alone since fluent reports hide technical errors.
- **Deployment:** track token cost per report when adding grounding context.
